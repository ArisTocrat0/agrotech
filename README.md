# Olzha Agro — поиск предполагаемых сорняков

MVP на Python 3.10+ для анализа снимков полей с дрона без bounding-box разметки. Выделяет области растительности, сопоставляет их с эталонными фотографиями по виду и стадии, считает кандидатов, сохраняет рамки, JSON и CSV. YOLO автоматически не обучается.

## Архитектура

Исходное фото → EXIF orientation / RGB → перекрывающиеся тайлы → HSV / Excess Green → морфология и связные компоненты → crop с padding → DINOv2 → среднее top-k cosine similarity внутри каждой группы `(species, stage)` → порог unknown → глобальные координаты → NMS по виду и стадии → результаты.

`combined` означает пересечение HSV и ExG масок. ExG вычисляется в знаковой арифметике: `2*G-R-B`. Координаты рамок относятся к изображению **после применения EXIF**, формат `x1,y1,x2,y2`, правая и нижняя границы исключены. Полный кадр не уменьшается. Crop дополняется до квадрата и масштабируется до 224×224 без искажения пропорций. Вектор CLS нормализуется по L2.

## Подготовка данных

```text
data/Сорняки/Бодяк полевой/Розетка/example.jpg
data/Сорняки/Бодяк полевой/Стеблевание/example.jpg
data/Сорняки/Пырей ползучий/Стеблевание/example.jpg
data/ФотоПолей/DJI_0001.JPG
```

Первый уровень под `Сорняки` — вид, второй — стадия; классы не зашиты в код. Более глубокие подпапки поддерживаются. JPG/JPEG/PNG и кириллица поддерживаются. Файлы без двух уровней меток пропускаются с предупреждением. Повреждённые изображения приводят к явной ошибке. Датасеты, веса, результаты и окружение исключены из Git.

## Установка

Из корня проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Для CUDA нужна сборка PyTorch, совместимая с вашей системой. `--device auto` выбирает CUDA при доступности, иначе CPU; поддерживаются также `cpu`, `cuda`, `cuda:0`. Первый запуск скачивает `facebook/dinov2-small` из Hugging Face и требует интернета; последующие используют кеш модели. При недоступности сети загрузите модель заранее в окружении с доступом к Hugging Face.

## Индекс эталонов

```bash
python scripts/build_reference_index.py --references "data/Сорняки" --output artifacts/reference_index.pt --device auto
```

Индекс содержит пути, метки и L2-нормализованные эмбеддинги. Кеш проверяется по SHA-256 содержимого эталонов, путям, меткам, имени модели и версии preprocessing. Для принудительного пересчёта добавьте `--force`. Изменения эталонов вызывают перестроение индекса. Изображения обрабатываются батчами, модель загружается один раз на процесс.

## Запуск

```bash
python run.py --references "data/Сорняки" --input "data/ФотоПолей" --output outputs
python run.py --references "data/Сорняки" --input "data/ФотоПолей/DJI_0001.JPG" --output outputs
```

Параметры: `--config config.yaml`, `--device cpu`, `--tile-size 1024`, `--overlap 0.20`, `--similarity-threshold 0.55`. Остальные пороги и batch_size задаются в `config.yaml`. При малом объёме видеопамяти уменьшите `model.batch_size`.

## Отладка

```bash
python run.py --references "data/Сорняки" --input "data/ФотоПолей" --output outputs --debug
```

`outputs/debug/` содержит тайлы, маски, рамки компонентов и crops. Ограничения `debug.max_tiles: 10`, `debug.max_crops: 50` действуют на весь запуск. При повторном запуске старые отладочные файлы не удаляются; для отдельного эксперимента используйте другую папку `--output`.

## Результаты

`outputs/annotated/` содержит PNG исходного разрешения с рамками и подписями `<вид> | <стадия> | sim=0.82`. Для кириллицы автоматически ищется DejaVu, Liberation или Noto; установите один из этих шрифтов, если системного шрифта нет. В крайнем fallback подписи могут не содержать кириллических глифов, но обработка не прерывается.

`outputs/results.json` — массив результатов, даже для одного кадра:

```json
[
  {
    "image": "DJI_0001.JPG",
    "width": 4096,
    "height": 3072,
    "total_weeds": 1,
    "total_candidates": 1,
    "unknown_count": 0,
    "counts_by_species": {"Бодяк полевой": 1},
    "counts_by_species_and_stage": {"Бодяк полевой__Розетка": 1},
    "detections": [
      {"id": 1, "species": "Бодяк полевой", "stage": "Розетка", "similarity_score": 0.84,
       "bbox": {"x1": 100, "y1": 200, "x2": 300, "y2": 450}}
    ]
  }
]
```

`total_weeds` — число кандидатов с известной меткой после NMS, `unknown_count` — неизвестные, `total_candidates` — их сумма. Это оценка числа объектов, а не подтверждённый подсчёт растений. Unknown сохраняются в detections и CSV, но не входят в счётчики видов. Вложенные исходные пути сохраняются относительно `--input`, чтобы одинаковые имена файлов не конфликтовали.

`outputs/results.csv` использует UTF-8 BOM для Excel. Колонки: `image,detection_id,species,stage,similarity_score,x1,y1,x2,y2`. Фото без обнаружений присутствует в JSON; CSV содержит только строки обнаружений.

## Ограничения

Точность не измерена. Маска выделяет зелёную растительность, включая культурные растения. Касание листьев может объединять несколько растений, разрывы маски — дробить одно. Мелкие сорняки, тени, сухие растения и отличия освещения ухудшают результат. Эталонные фотографии крупным планом могут сильно отличаться от снимков с дрона. Без эталонов культурных растений и проверки на полевых данных неизвестные объекты могут получать ошибочный известный класс.

`similarity_score` — сходство, **не вероятность**; порог 0.55 является стартовым и требует настройки. Группа с числом эталонов меньше top-k использует все свои эталоны. Вид и стадия не гарантируются. Частичные рамки на краях тайлов и конфликтующие классы могут оставаться дубликатами после NMS. Плотные посадки не дают достоверного подсчёта отдельных растений. MVP не предназначен для автоматического принятия решений о гербицидах.

## Экспорт pseudo-labels

```bash
python scripts/export_pseudo_yolo.py --results outputs/results.json --images "data/ФотоПолей" --output pseudo_dataset --min-similarity 0.70
```

Создаются `images/`, `labels/`, `dataset.yaml`, `source_images.json`. Класс — `species__stage`; список формируется автоматически и сортируется. Формат каждой строки: `class_id x_center y_center width height`, координаты нормализованы в 0..1. Unknown и слабые совпадения пропускаются. Фото без принятых рамок исключаются: отсутствие предсказаний не означает проверенный отрицательный пример. Изображения сохраняются как PNG с применённой EXIF orientation. `source_images.json` связывает экспорт с оригиналами для будущего разделения данных. Повторный экспорт требует пустой/новой папки, чтобы не смешать старые классы.

`dataset.yaml` имеет схему Ultralytics, однако `train` и `val` пока указывают на одну папку **только как временный шаблон экспорта**. Нельзя использовать этот шаблон для оценки качества. Сначала проверьте разметку и создайте раздельный `yolo_dataset/dataset.yaml`.

## Переход на YOLO

MVP → pseudo-labels → ручная проверка в CVAT / Roboflow / Label Studio → разделение train/val/test **по исходным DJI-фото** → tiling → обучение YOLO. При проверке исправляйте не только ложные рамки, но и пропущенные растения.

Тайлы одного исходного кадра не должны попадать одновременно в train и val/test: это утечка данных. Соседние перекрывающиеся кадры одного пролёта желательно также группировать. Сохраните единый список классов для всех частей. Оцените precision/recall на вручную размеченной отложенной выборке.

Пример будущего обучения после подготовки корректного разделения:

```bash
pip install ultralytics
yolo detect train model=yolo11s.pt data=yolo_dataset/dataset.yaml imgsz=1024 epochs=100 batch=8 device=0
```

Для слабого GPU: `model=yolo11n.pt batch=4`. Интерфейс `VegetationDetector.detect(image) -> list[DetectionCandidate]` позволяет заменить источник кандидатов детектором YOLO.

## Проверки

```bash
python -m compileall .

```

Smoke-тесты не скачивают DINOv2: проверяют импорты, IoU/NMS, покрытие тайлами, конфиг, подсчёт unknown, синтетическую сегментацию, pipeline с подставной классификацией, JSON/CSV, нормализацию YOLO и EXIF-экспорт. Они не измеряют качество реальной модели.

## Веб-интерфейс

```bash
cd /home/beka/Projects/agrotech
source .venv/bin/activate
python web_app.py
```

Откройте **http://127.0.0.1:8000**. Дополнительных зависимостей для интерфейса не требуется. Для другого порта: `python web_app.py --port 8080`. Остановка — Ctrl+C; текущий анализ при этом также останавливается. Сервер предназначен для локальной работы и слушает только 127.0.0.1.

- **Обзор полей**: показатели выбранного анализа, распределение видов, история и фотографии с рамками. Нажатие на снимок открывает его в увеличенном виде.
- **Новый анализ**: перетащите JPG/PNG или выберите файлы. До 20 снимков, суммарно до 99 МБ на стороне интерфейса (сервер принимает до 100 МБ вместе с формой). Обработка идёт в отдельном процессе, состояние обновляется автоматически. Одновременно выполняется один анализ.
- **Выгрузка данных**: скачивание полного JSON или CSV для Excel, предпросмотр первых 100 обнаружений. Выбранный анализ общий для дашборда и выгрузки.

Для реального анализа нужны зависимости из `requirements.txt` и эталоны в `data/Сорняки/Вид/Стадия/`. При первом запуске скачивается DINOv2. При отсутствии эталонов или ошибке модели интерфейс покажет сообщение. Показатели рассчитываются по фактическим результатам; демонстрационные находки не подставляются. Графика поля в верхнем баннере — декоративная иллюстрация.

Загрузки, результаты и лог каждого запуска сохраняются в `outputs/web/<id>/`. История сохраняется после перезапуска сервера. Существующие `outputs/results.json` и CSV от CLI также доступны в интерфейсе как «Результаты из терминала». JSON и CSV выгружаются без изменений. Эталоны загружаются через папку на диске; формы для их редактирования пока нет.

```bash

```

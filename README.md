# Olzha Agro — мониторинг полей

Локальный сайт для анализа снимков полей с дрона. Выделяет области растительности, сравнивает их с эталонами по виду и стадии роста, показывает предполагаемые сорняки и сохраняет результаты.

## Установка и запуск сайта

Нужен Python 3.10+. При первой установке из папки проекта:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Запуск сайта из основной папки проекта, где находится `web_app.py`:

```bash
cd /home/beka/Projects/agrotech
source .venv/bin/activate
python web_app.py
```

Откройте **http://127.0.0.1:8000**. После запуска работа с эталонами, проверками, анализом и результатами выполняется в браузере. Для остановки сервера нажмите Ctrl+C; текущая обработка также остановится. Сервер слушает только локальный адрес 127.0.0.1. Другой порт можно указать при запуске: `python web_app.py --port 8080`.

## Работа через интерфейс

### 1. Подготовка

Откройте вкладку **«Подготовка»**.

- Укажите **вид растения** и **стадию роста**, выберите эталонные фотографии и нажмите **«Сохранить эталоны»**. Повторите для других видов и стадий. Принимаются JPG/JPEG/PNG, до 20 файлов общим размером до 99 МБ за одну загрузку.
- Таблица **«Загруженные эталоны»** показывает доступные группы и количество фотографий. Ранее добавленные эталоны также отображаются. Файлы сохраняются автоматически; создавать папки вручную не нужно.
- Нажмите **«Запустить проверку»**. Статус и подробный отчёт появятся на странице и обновятся автоматически. Проверка использует синтетические изображения, проверяет компоненты обработки и экспорт, не скачивает модель и не измеряет точность на реальном поле.

Во время анализа добавление эталонов временно недоступно, чтобы набор образцов не менялся в процессе обработки. Индекс эталонов строится автоматически при запуске анализа и обновляется при изменении фотографий.

### 2. Новый анализ

Перейдите на вкладку **«Новый анализ»**, выберите снимки поля или перетащите их в область загрузки. До 20 снимков общим размером до 99 МБ; сервер допускает до 100 МБ вместе с формой.

В разделе **«Настройки анализа»** доступны:

| Настройка | Назначение |
| --- | --- |
| Устройство | Автоматический выбор, CPU или CUDA GPU |
| Размер тайла | Размер участка обработки, от 128 до 4096 пикселей |
| Перекрытие тайлов | Доля перекрытия соседних участков, от 0 до 0.99 |
| Порог сходства | Минимальное сходство с эталоном для определения вида, от −1 до 1 |
| Размер пакета | Число изображений в пакете, от 1 до 128; уменьшите при нехватке видеопамяти |
| Отладочные изображения | Сохранение тайлов, масок, компонентов и вырезанных областей |

Нажмите **«Начать анализ»**. Одновременно выполняется один анализ. По умолчанию DINOv2 загружается только из локального кеша. Для первого скачивания из Hugging Face включите «Разрешить загрузку модели из интернета»; для последующих запусков достаточно кеша. Для CUDA требуется совместимая сборка PyTorch и видеокарта. При выборе CPU GPU не требуется.

Можно переходить между вкладками во время обработки. Результаты появятся автоматически. Внизу страницы находится **«Журнал анализа»**: выберите запуск, чтобы посмотреть ход обработки или подробности ошибки прямо в браузере.

### 3. Просмотр и проверка результатов

Во вкладке **«Обзор полей»** выберите завершённый анализ. Сайт покажет количество снимков, предполагаемых сорняков, найденных видов и неизвестных объектов, а также распределение видов и историю запусков.

Нажмите на снимок, чтобы увеличить изображение с рамками. Проверьте найденные объекты визуально: это предварительные результаты, требующие оценки агрономом. Декоративная иллюстрация поля в баннере не является результатом анализа.

### 4. Выгрузка

Во вкладке **«Выгрузка данных»** доступны:

- **JSON** — полные результаты, включая снимки без обнаружений.
- **CSV** — таблица обнаружений в UTF-8 BOM для Excel.
- **ZIP** — результаты, снимки с рамками, журнал и отладочные изображения, если они были включены.
- **Разметка YOLO** — архив изображений и предварительных меток с порогом сходства 0.70. Доступен для анализов, запущенных через сайт. Если подходящих объектов нет, сайт покажет сообщение.

Предпросмотр таблицы содержит до 100 обнаружений; скачиваемые файлы содержат все результаты. Поле `similarity_score` означает сходство с эталоном, а не вероятность.

YOLO-экспорт предназначен для дальнейшей ручной проверки. Неизвестные виды и слабые совпадения пропускаются. Фото без принятых рамок исключаются, поскольку они не являются проверенными отрицательными примерами. Перед обучением необходимо исправить ложные рамки и пропущенные растения, затем разделить данные по исходным фотографиям на обучающую и проверочную выборки. В экспортном `dataset.yaml` train и val указывают на одну папку как временный шаблон. Пробное обучение YOLO доступно на вкладке «Подготовка». Сайт пока анализирует поля с помощью DINOv2; обученные веса YOLO не подключаются к анализу автоматически.

### 5. Пробное обучение YOLO

На вкладке **«Подготовка»** находится блок **«Пробное обучение YOLO»**. Нажмите **«Запустить пробное обучение»**: прогресс по эпохам и журнал обновляются автоматически. После завершения доступна кнопка **«Скачать веса YOLO»**. Повторный запуск создаёт отдельную папку и не перезаписывает предыдущие результаты. Закрытие страницы не останавливает обучение.

Текущий пробный режим: YOLO11n, CPU, 5 эпох, изображения 320×320, пакет 4, seed 42. Исходные веса находятся в `artifacts/yolo11n.pt`, подготовленный датасет — в `yolo_dataset/trial/`, результаты — в `outputs/yolo_training/<запуск>/` (`weights/best.pt`, `weights/last.pt`, `results.csv`, `args.yaml`, `training.log`). Для нового развёртывания эти локальные файлы нужно перенести отдельно: данные и веса не хранятся в Git. Параметры обучения соответствуют [документации Ultralytics](https://docs.ultralytics.com/modes/train/).

Данные скопированы из соседней рабочей папки `yolo-training-initiation`: 59 обучающих, 20 проверочных и 12 тестовых тайлов из 5 исходных снимков. Исходные снимки между выборками не пересекаются. Тестовая выборка в пробном обучении не используется. Разметка автоматическая и не проверена вручную; класс «Бодяк полевой — Стеблевание» отсутствует в обучающей выборке. Метрики на такой разметке показывают согласие с автоматическими метками, а не подтверждённую точность распознавания сорняков. Перед полноценным обучением нужно проверить рамки и дополнить данные для всех классов.

### Язык

Переключатель **RU / EN / KZ** вверху страницы меняет язык интерфейса на русский, английский или казахский. Выбор сохраняется в браузере. Имена файлов, пользовательские названия видов и стадий, а также технические журналы остаются в исходном виде.

## Хранение данных

- Эталоны: `data/Сорняки/<вид>/<стадия>/`. Интерфейс создаёт структуру самостоятельно; JPG/JPEG/PNG и кириллица поддерживаются.
- Кеш индекса: `artifacts/reference_index.pt`. Проверяется по содержимому изображений, меткам, путям, имени модели и версии предобработки.
- Анализы: `outputs/web/<id>/`. Сохраняются входные изображения, настройки запуска, журнал и результаты. История доступна после перезапуска сервера.
- Существующие результаты в `outputs/results.json` также отображаются на сайте. Для них YOLO-экспорт через сайт недоступен, поскольку исходные изображения не привязаны к запуску.

Датасеты, веса, результаты и окружение исключены из Git.

## Как выполняется анализ

Исходное фото → применение EXIF orientation → RGB → перекрывающиеся тайлы → HSV / Excess Green → морфология и связные компоненты → crop с отступом → DINOv2 → среднее top-k cosine similarity внутри группы `(вид, стадия)` → порог unknown → глобальные координаты → NMS → результаты.

Полный кадр не уменьшается. Вырезанная область дополняется до квадрата и масштабируется до 224×224. Рамки относятся к изображению после применения EXIF: `x1,y1,x2,y2`, правая и нижняя границы исключены. `combined` использует пересечение HSV и ExG; ExG вычисляется как `2*G-R-B` в знаковой арифметике.

`total_weeds` — объекты категории «Сорняк» после NMS и ручной проверки, `crop_count` — культуры, `unknown_count` — объекты на проверку, `rejected_count` — отклонённые объекты. `total_candidates` включает все четыре категории. Неизвестные объекты сохраняются в JSON и CSV, но не входят в счётчики видов. CSV содержит одну строку на обнаружение: `image,detection_id,species,stage,similarity_score,kind,review,x1,y1,x2,y2`.

## Ограничения

Точность на полевых данных не измерена. Маска выделяет зелёную растительность, включая культурные растения. Касающиеся листья могут объединять несколько растений, а разрывы маски — дробить одно. Мелкие сорняки, тени, сухие растения и отличия освещения ухудшают результат.

Эталоны крупным планом могут сильно отличаться от снимков с дрона. Вид и стадия не гарантируются, возможны дубликаты на границах тайлов. Порог 0.55 — стартовая настройка. Плотные посадки не дают достоверного подсчёта отдельных растений. MVP не предназначен для автоматического принятия решений о гербицидах.


## Проверка растений и масштаб снимка

При добавлении эталонов выбирайте тип «Сорняк» или «Культура». Для пшеницы,
ячменя и подсолнечника предусмотрена кнопка импорта фотографий с Wikimedia
Commons; загрузка требует интернета. Такие фотографии нужно проверить на
пригодность для ваших снимков с дрона.

В окне снимка можно выбрать рамку и назначить категорию клавишами 1–4:
сорняк, культура, не растение, не уверен. Решения сохраняются в `reviews.json`
отдельно от исходных предсказаний. При смене категории прежние вид и стадия
не считаются подтверждёнными.

Масштаб задаётся в сантиметрах на пиксель при запуске анализа или в окне
проверки. Например, кадр 1000×1000 пикселей при GSD 1 см/пиксель имеет площадь
100 м². Без масштаба плотность не рассчитывается. Кнопка «Рассчитать ряды и
площадь» сохраняет масштаб и оценку рядов в `geometry.json`. Плотность относится
к обнаруженным объектам; объединённые растения и пропуски влияют на результат.

## Ускорение на C++

Удаление повторяющихся рамок (NMS) реализовано в `native/nms.cpp` и подключается
через `ctypes` в `src/vision/nms.py`. Файл `src/nms.py` сохраняет совместимость
со старыми импортами. Для сборки в Linux нужен `g++` с поддержкой C++17:

```bash
.venv/bin/python scripts/build_native.py
.venv/bin/python scripts/test_nms.py
.venv/bin/python scripts/test_review.py
.venv/bin/python scripts/benchmark_native.py
```

Библиотека сохраняется в `artifacts/native/libagro_nms.so`; после сборки
перезапустите запущенный сервер. По умолчанию `backend='auto'` использует C++,
если библиотека доступна, иначе Python. `backend='cpp'` требует C++ и сообщает
об ошибке при отсутствии библиотеки; `backend='python'` удобен для сравнения.
Порядок рамок с одинаковым сходством сохраняется. Подавление выполняется
только внутри одной пары «вид, стадия» при IoU строго выше порога.

Бенчмарк требует собранную библиотеку, проверяет совпадение результатов и
сохраняет медиану пяти замеров для 1500 рамок в `artifacts/benchmark_nms.json`.
Он измеряет NMS вместе с передачей данных из Python в C++, но не DINOv2,
обработку полного кадра или FPS всей системы.

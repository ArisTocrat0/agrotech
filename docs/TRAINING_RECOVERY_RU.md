# Восстановление разрешённых прогонов после сбоя

Текущие training/supervisor не перезапускались. Автозапуск обучения и системные службы не устанавливались. При выключенном ПК обучение невозможно; этот скрипт запускается вручную после входа и проверки причин сбоя.

Проверка на хосте (по умолчанию без запуска обучения):

```bash
cd /home/beka/Projects/agrotech
.venv/bin/python scripts/recover_quality_training.py --run litter-v3-land-yolo11n-full-cpu-20261020
```

Выполнение после сбоя: та же команда с `--execute`. Запускать на хосте с видимыми `/proc` существующих процессов и доступом записи к проекту, а не в изолированном PID namespace. Пока trainer или supervisor жив, даже `--execute` возвращает `no_op_live_workers`. Скрипт не посылает сигналов. Вторая защита — общий эксклюзивный training.lock. Он удерживается до конца восстановления и оценки.

Для smoke разрешено только имя `smoke-pyrosdis-yolo11n-cpu-20261020`, и только если этот прогон действительно уже был начат. Восстановление никогда не создаёт новый прогон и не начинает следующий этап smoke автоматически.

Проверяются замороженные snapshot/manifest/data и исходные веса, параметры checkpoint, класс, optimizer/EMA, конечность весов, совпадение завершённой эпохи checkpoint и progress, прежние patience и абсолютный срок. При разрыве checkpoint/progress, повреждении checkpoint, записи failure.json или истёкшем бюджете скрипт останавливается с конкретной причиной. Бюджет автоматически не продлевается. Начальная эпоха/optimizer/EMA восстанавливаются через локальный Ultralytics resume; ранняя остановка восстанавливается из истории, чтобы не обнулить patience.

Checkpoint записывается в конце эпохи; текущая незавершённая эпоха после сбоя может повториться. Checkpoint этой версии основан на EMA/fp16 optimizer и не сохраняет полный RNG и состояние загрузчика. Побитово идентичное продолжение не обещается. Повреждённый last.pt не заменяется молча на best.pt.

Состояние старого supervisor, его SHA256, progress и хеши имеющихся threshold/consumed-маркеров сохраняются перед выполнением в уникальный recovery-snapshot-*.json; старый supervision.json не перезаписывается. Отдельное recovery-supervision.json фиксирует восстановленную оценку. Завершённая оценка — no-op; экспорт/оценка продолжаются без новой калибровки, если lock/cache проходят прежние проверки. Отдельный старый supervisor повторно не запускается: восстановитель сам последовательно завершает работу.

Ничего не активируется. Нужны прежние parity, визуальный разбор и manual-review; Fire baseline, реестр, 22 фото и история остаются на месте.

Проверено: синтаксис, защита live --execute на реальных PID, четыре теста (live no-op, отказ для не начатого smoke, изменённого snapshot и сохранение patience). Реальный crash/resume не воспроизводился: прерывать текущий прогон запрещено. Экспорт/оценка через восстановитель пока не выполнялись.

## Демонстрация за 5 минут

1. «Обзор»: объяснить, что дрон отсутствует, приём — отдельные загружаемые фото, не live-видео.
2. «Приём снимков»: выбрать ID миссии и JPEG/PNG. Время съёмки оставить неизвестным, если его нет; GPS вводить только при наличии реального источника.
3. Показать переход `В очереди → Обработка → Готово` или явную ошибку. Несколько файлов загружаются последовательно, модель обрабатывает один снимок за раз.
4. «Журнал находок»: открыть кадр с рамками, посмотреть исходный кадр, подтвердить/отклонить гипотезу. Даже при нуле находок снимок остаётся в журнале.
5. Повторно загрузить то же фото в ту же миссию — новый анализ не создаётся. Различающиеся GPS/время/режим у дубликата отвергаются, чтобы не переписать происхождение.
6. «Карта»: точки камеры только по имеющимся GPS. Без GPS карта честно остаётся без маркеров. `object_location` всегда null: геометрия камеры/высота/рельеф не заданы. GeoJSON сохраняет null geometry для событий без GPS.
7. «Обучение»: показать версии, действительные метрики и ограничения. Число рамок на соседних фото не равно числу физических объектов.

Воспроизводимая загрузка имеющихся публичных примеров:

```bash
.venv/bin/python scripts/demo_photos.py --weeds --mission local-reference-demo
```

Примеры явно помечены `metadata.demo=true`, это не наблюдения в Казахстане. Координаты и время не добавляются. Прогон не подтверждает находки автоматически.

## Что реализовано

- Отдельный интерфейс «Экокинеу»: обзор, приём снимков, журнал, офлайн-карта мира с приближением точек, обучение.
- MariaDB, долговечная FIFO-очередь, ID миссии, отдельно время съёмки и приёма, необязательные координаты и JSON-метаданные.
- Защита от точных дублей SHA256 в рамках миссии, последовательный worker, блокировка второго worker.
- При рестарте задачи `running` получают явную ошибку, `queued` продолжаются. Повтор ошибки запускается кнопкой; подтверждения хранятся в БД.
- Исходные байты фото, SHA256, нормализованный исходный JPEG и JPEG с рамками. Версия модели/порог/размер входа записаны в результате.
- Экологический worker написан на Python и вызывает **OpenVINO Python API с нативным C++ runtime**. `native/infer_openvino.cpp` — самостоятельный инструмент проверки/замеров; рабочий pipeline целиком на C++ не переписан.
- Существующий offline DINOv2 + эталоны сорняков + C++ NMS адаптирован к общей очереди. Cosine similarity отображается как сходство, не вероятность. Качество поиска на поле не измерено.
- Проверка находок человеком, JSON/GeoJSON, локальные evidence. Сторонние сервисы не вызываются.

Исходный расширенный интерфейс эталонов/разметки доступен отдельно через `.venv/bin/python web_app.py --legacy --port 8001`, вкладка «Обучение». Он сохранён для совместимости; обучение YOLO на старой псевдоразметке не используется для экологического пилота. Не запускайте тяжёлый анализ/обучение одновременно на этой машине без контроля RAM.

## Границы качества

Текущий профиль мусора: DroneWaste500 transfer, 3 эпохи / 320px / freeze10, около717.8с. Train350/val75/test75, площадки разделены. Test mAP50=0.1586, mAP50–95=0.0725, precision≈0.238, recall≈0.243. Это эксперимент с недостаточным качеством, не надёжная система обнаружения. Он относится к свалкам/кучам из ортомозаик, не к мелкому уличному мусору. Порог выбирается по validation75 (max meanF1), а не test. Исходная COCO-разметка сохраняется, производные target-метки могут дедуплицироваться библиотекой после объединения категорий; проверять фактические instances в логах.


Первый запуск мусора (история, уже не текущий профиль): 48 train / 12 validation / 12 test, 8 эпох, 320px. mAP50 на 12 test ≈0.115, mAP50–95≈0.041. Это слабый экспериментальный baseline. На части демонстрационных фото при пороге 0.35 он не выдаёт находок, несмотря на наличие объектов. Нулевой результат не означает чистую/безопасную территорию.

Результат см. `artifacts/pilot_training.json` и `outputs/pilot-training/<run>/report.json`. Он не заменяет рабочие веса автоматически. Тест никогда не участвует в градиентах или выборе checkpoint; после повторных экспериментов этот небольшой test уже не следует считать полностью независимым финальным приёмочным набором.

Fire/smoke: активный baseline `Mahadih534/person-smoke-fire`, pinned revision `4a60bd37bdd2941459191c1e7caab85e17dcdc0a` (точный SHA — SOURCE.json), карточка весов CC BY 2.0; код/export/runtime Ultralytics AGPL-3.0. 22.5МБ checkpoint проверен SHA256 и преобразован только через `torch.load(weights_only=True)` с явным списком известных nn.Module классов установленной библиотеки. Worker использует только OpenVINO IR, не десериализует внешний pickle. Класс person явно исключён. На публичном Waldbrand-примере получены две рамки видимого огня, ночной пример пропущен. Эти фото не дают независимой метрики: происхождение train этой модели неизвестно и примеры могли в него входить. Качество на воздушных снимках не измерено. Предыдущий INT8 baseline zell-dev оставлен для воспроизводимости/отката, он пропустил оба выбранных примера при рабочем пороге и не является текущим fire-детектором.

Голова сорняков обучена повторно на проверенных SHA256 старых эталонах, новый каталог `artifacts/weed-runs/<UTC>/`, прежние веса сохранены. 332 train / 110 validation / 110 test; test accuracy≈0.982 относится только к классификации эталонных фото трёх видов, не к детекции с воздуха. Текущая очередь сорняков использует существующий reference baseline, а не автоматически активирует новую голову.

## API приёма снимка

`POST /api/pilot/photos`, JSON, до 15 МБ запроса / 10 МиБ фото. Сервер только loopback; это локальный контракт, не аутентифицированный production ingestion.

```json
{
  "mission": "inspection-2026-10-21",
  "name": "chunk-001.jpg",
  "photo": "BASE64_OF_REAL_JPEG_OR_PNG",
  "captured_at": null,
  "analysis_mode": "environment",
  "location": null,
  "metadata": {"camera": "unknown"}
}
```

Время если известно: ISO8601 с часовым поясом. Для известного GPS: `location:{latitude:...,longitude:...,source:"operator_capture_position"}`. Иначе GPS EXIF извлекается из оригинальных байтов; никаких дефолтных координат. Режим `weeds` — отдельный анализ сорняков; чтобы обработать то же фото другой моделью, используйте другую миссию, сохраняя связь в метаданных.

`GET /api/pilot/photos`, `GET /api/pilot/status`, `GET /api/pilot/events.geojson`; `POST /api/pilot/photos/<id>/retry`, `POST .../<id>/review` с `event_id` и `status` (`confirmed`, `rejected`, `unreviewed`).

Хранилище: `outputs/pilot/<id>/{original,source.jpg,annotated.jpg,result.json}`; актуальные решения проверяющего — в MariaDB, `result.json` является снимком исходного вывода модели. Исходники/веса/секреты не выдаются через HTTP. Результаты доступны любому локальному пользователю, имеющему доступ к серверу; для production это нужно закрыть.

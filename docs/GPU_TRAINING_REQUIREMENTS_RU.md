# Внешнее обучение: требования, без запуска облака

Нужна возможность выполнить **собственный Python/PyTorch CUDA-процесс**, читать свой датасет и сохранить `.pt`/экспорт. Endpoint готовой модели для inference этих возможностей сам по себе не даёт. Предложен https://build.nvidia.com/explore/discover — каталог hosted NIM inference API; он не предоставляет нам произвольную CUDA-машину для запуска этого обучения. Дополнительный GPU-доступ не получен, локальный CPU-план сохраняется. Здесь нет запроса ключа, покупки мощности или разрешения передачи фото наружу.

Для YOLO11n на 640px разумная стартовая заявка: **одна NVIDIA GPU с 8 ГБ VRAM**, предпочтительно 12–16 ГБ, 4 vCPU, 16 ГБ RAM и не меньше 20 ГБ свободного диска. Это инженерный ориентир для batch 4–8, не измеренный минимум конкретной GPU. После выбора машины сначала проверить CUDA и расход памяти на коротком запуске; при OOM уменьшить batch. Не выбирать платную услугу без сведений о ней и лимита расходов.

Среда: Linux x86_64, совместимые NVIDIA driver/PyTorch CUDA wheel, Ultralytics 8.4.154 (текущий проверенный API), зависимости проекта. Версии Python/PyTorch и CUDA проверить вместе для выбранного образа, не менять системные драйверы Fedora ради удалённой машины. Текущая Fedora: CUDA недоступна; CPU Ryzen5 3500U, RAM5.7GiB. UAVVaste20эпох заняли около28мин; у DroneWaste первый CPU-epoch350фото — около200с. Срок на GPU до измерения её первой эпохи не обещается.

Данные: отдельно DroneWaste500-v1, PNG640×640, неизменные площадочные split350/75/75, YOLO labels одного класса `trash`, исходный COCO20классов/manifest/CC BY4.0 сохраняются. Производные labels исключают category18 Asbestos: 1734/209/243 рамок. GPS/времени нет. Это кучи/свалки из ортомозаик, не доказательство качества на одиночной уличной бутылке. UAVVaste и пользовательские фото не добавлять в этот набор автоматически.

После отдельного разрешения на конкретную внешнюю машину/передачу данных подготовленный public-набор можно разместить или воспроизвести на ней. Ссылки в репозитории не содержат сами PNG; восстановить их к подтверждённому пути набора:

```bash
python scripts/integrate_dronewaste500.py /confirmed/path/ecokineu_dronewaste_500 --restore-links
# Пример контролируемого GPU-прогона, не выполнялся:
python scripts/train_pilot.py --device 0 --batch 8 --epochs 30 --imgsz 640 --freeze 0 \
  --name dronewaste500-gpu-v2 --data datasets/dronewaste500-v1/dataset.yaml \
  --model /confirmed/path/trusted-initial-weights.pt
```

Инициализация: собственные доверенные веса YOLO11n, SHA записать; transfer из UAVVaste должен явно указывать происхождение (веса обучены на train48, не test12). Нельзя подменять test при подборе параметров. Checkpoint выбирается только по val75; test75 — финальный отчёт. Новый независимый полевой test потребуется после экспериментов. Фото пользователя внешнему сервису не передавались и не входят в разрешённую передачу.

Выход: `best.pt`, `last.pt`, `args.yaml`, `results.csv`, `report.json`, calibration по val, manifest/checksum среды; локально безопасный OpenVINO IR `.xml+.bin` для C++ backend. Дополнительный ONNX фиксированного batch1 и размера640 возможен при необходимости. На Fedora сравнить реальные выходы/latency перед активацией, сохранить старый registry для отката. Секреты — через штатный защищённый механизм выбранной машины, не в Git или чат.

Официальные параметры device/batch/validation: [Ultralytics Train](https://docs.ultralytics.com/modes/train/). Форматы экспорта и параметры: [Ultralytics Export](https://docs.ultralytics.com/modes/export/). Размер VRAM выше — наша предварительная оценка, не гарантия из документации.

# Экологический анализ фотографий: первый этап

Открывается отдельно: `http://127.0.0.1:8000/environment.html` после `python web_app.py`.
Существующие анализы сорняков, эталоны, обучение и старый AI-чат сохраняют свои маршруты и формат.
Изменяется только **agrotech**. В AgroMindKZ, n8n, DJI и внешних системах ничего не изменяется.

## Что реализовано

- Только фотографии JPG/JPEG/PNG: до 10 фото, 100 МиБ вместе с формой, 8000 px по стороне и 25 Мп на фото. Видео не принимается.
- Отдельный локальный детектор Ultralytics object detection для явно настроенных классов `trash`, `fire`, `smoke`. Фильтр растительности DINOv2 не используется.
- Оригинальные загруженные байты сохраняются в `outputs/environment/<job>/input/`; нормализованные фото, рамки и confidence — в `evidence/`. SHA256 оригинала записывается в результат.
- Все обнаружения имеют статус `unreviewed`. Это визуальные предположения, не доказанные пожары или загрязнения. `confidence` — оценка модели, не измеренная надёжность системы.
- JSON с событиями и GeoJSON. Геометрия — только позиция съёмки с источником координат, **не точное положение объекта в рамке**. При неизвестных координатах `geometry: null`; фиктивных точек и привязки к региональному центру нет.
- Координаты берутся из явно заданных оператором полей/JSON либо из GPS EXIF оригинального фото. Значения оператора имеют приоритет. EXIF без корректного GPS не порождает точку. Поворот EXIF учитывается при обработке.
- Схема координат без внешних карт/тайлов; фото и координаты не покидают сервер при обычном анализе.
- Частичные ошибки показываются явно. Если ни одно фото не обработано, задача получает `error`. На POSIX установлен кооперативный таймаут 15 минут через SIGALRM; Python может отложить его во время native C вызова. Это не жёсткая гарантия остановки зависшего декодера/модели; одновременно допускается один анализ с существующими задачами сорняков.

Нет управления полётом, live-потока, автоматических уведомлений экстренным службам или определения химического состава загрязнения. Отсутствие обнаружений **не означает безопасную территорию**. Ночной/скрытый огонь и тление по обычной камере могут быть пропущены.

## Модель: настройка обязательна

Веса не включены и не скачиваются автоматически. Без них статус `model_not_configured`, запуск закрыт, загруженные фото не сохраняются. Нужны доверенные локальные веса, лицензия на использование и полевые испытания.

```bash
export AGRO_ENV_MODEL=/absolute/path/to/trusted-environment-model.pt
export AGRO_ENV_CLASS_MAP='{"litter":"trash","flame":"fire","smoke":"smoke"}'
python web_app.py
```

Ключи должны **в точности совпадать со всеми именами классов конкретных весов**. Пример не означает, что такие веса существуют в проекте. Значения разрешены только `trash`, `fire`, `smoke`; интерфейс показывает реально настроенный набор. Несоответствие классов или task приводит к ошибке. COCO `bottle` нельзя автоматически считать мусором; стандартная COCO-модель не обучена на пожар/дым.

Поддерживается API `ultralytics>=8.4.154,<9`, современная модель обнаружения в формате `.pt`, совместимая с этим пакетом, CPU. Старые оригинальные YOLOv5 checkpoints не объявляются совместимыми. Конкретные веса на реальном runtime здесь **не проверены**. `.pt` десериализуется библиотекой PyTorch и должен происходить из доверенного источника; неизвестные checkpoints небезопасны.

Порог 0.35 по умолчанию — начальная настройка, не результат калибровки. Нужно оценить отдельно пропуски/ложные тревоги для мусора, огня и дыма, разные высоты, сезоны, камеры, освещение; разделять выборки по полётам/местам. Нужны реальные размеченные фото DJI, включая отрицательные примеры. Никаких производственных процентов качества не заявляется.

Источники для будущей оценки (не скачаны и не включены):
- SODA aerial litter: https://github.com/danielopisani/SODA-Dataset — уточнить права на выбранные веса/код отдельно от датасета.
- D-Fire: https://github.com/gaia-solutions-on-demand/DFireDataset и https://github.com/pedbrgs/Fire-Detection — другие условия и YOLOv5 runtime; не подставлять `.pt` вслепую.
- Ultralytics inference: https://docs.ultralytics.com/modes/predict/

## Координаты

Поля широты/долготы означают общую известную позицию съёмки выбранных фото. Если позиции разные, задайте JSON по исходным уникальным именам:

```json
{"DJI_0001.JPG":{"latitude":53.2,"longitude":63.6,"source":"operator_capture_position"}}
```

Изображение с GPS EXIF можно загрузить без полей координат. GeoJSON указывает `geometry_role: capture_position_not_object` и `location_provenance`. Точная геолокация объекта потребует ориентации камеры, высоты с известным datum, калибровки/интринсик, рельефа и отдельной геометрической проверки. Соседние фотографии могут содержать один объект; сейчас количество событий не равно числу уникальных физических объектов.

## DJI: фото сейчас, транспорт после уточнения оборудования

Сейчас принимаются вручную загруженные фотографии, в том числе оригиналы DJI с EXIF. **Активное подключение к DJI API не реализовано**: модель дрона и пульта неизвестны. Универсального Python API для всех DJI нет.

Будущий входной `PhotoAsset` должен сохранять: источник/идентификатор медиа, исходные байты и SHA256, MIME/размеры, время с часовым поясом либо null, необязательные camera model, capture position/источник EXIF-XMP, высоту с datum, позу подвеса и intrinsics. Неизвестные поля остаются null. У события `object_location` остаётся null до отдельной геопривязки.

Выбор транспорта после уточнения модели/пульта:
- DJI Cloud API для поддерживаемых enterprise Pilot 2/пультов или Dock требует отдельной платформы, авторизации и хранилища. Сначала проверяются успешный callback и существование оригинала в storage, затем анализ. Прямой запрос к придуманному endpoint не делается.
- Mobile SDK v5 — отдельная Android-интеграция и конкретная матрица оборудования; это не зависимость Python-сервера.
- Матрица Cloud API: https://developer.dji.com/doc/cloud-api-tutorial/en/overview/product-support.html
- Android SDK: https://github.com/dji-sdk/Mobile-SDK-Android-V5

## AgroMind: отключённый по умолчанию v2 адаптер

Старый `/api/assistant` (crop-chat) оставлен как был. Новый экологический помощник использует отдельную настройку, не заменяет URL старого чата и не подменяет UUID настоящим ID.

```bash
export AGRO_ENV_AGROMIND_URL=https://your-confirmed-host.example/webhook/agromind-agronomist-v2
export AGRO_ENV_AGROMIND_USER_ID=123
```

Это пример, а не действующий адрес или ID. Администратор должен указать подтверждённый endpoint и настоящий положительный ID пользователя. Наличие ID в JSON не обеспечивает авторизацию; публично выставлять текущий локальный сервер нельзя.

Отправка выполняется только отдельной кнопкой с явным согласием на выбранное событие/координаты и вопрос. Фото требует отдельного opt-in; не более 5 МиБ/8000 px. Не отправляются оригинальное имя файла, локальные пути, весь набор фото или другие задачи. Payload: `schema_version:2`, positive `user_id`, `sessionId:null`, `message`, `history:[]`, `context.location`, `context.drone_observation`, необязательные raw base64 `image` + `mediaType:image/jpeg`. Ответ ожидается `{response: string}`. Redirect запрещён, автоматического повтора нет.

Пожарные события не зависят от ответа LLM. Рекомендации помощника не подтверждают безопасность и не вызывают службы. Production endpoint и live n8n **не проверялись и не вызывались**. Контракт основан на `Kalmat4/AgroMindKZ/docs/AGRONOMIST_N8N_RU.md` и `n8n-workflows/agronomist-v2.json` (main `45966fc7f3d4282e12718054af6cd05e3f6164aa`).

## Проверки

```bash
python -m unittest scripts.test_environment -v
node scripts/test_environment_ui.cjs
python -m compileall -q src scripts/analyze_environment.py
```

Тестовые детекторы и фальшивые checkpoints используются **только в unit-тестах**, явно помечены и не доступны пользователю через нормальный запуск. Проверки покрывают валидацию фото, EXIF/координаты, отсутствие модели, class mapping, рамки/NaN, сохранение доказательств, частичные ошибки, отдельную историю/HTTP, согласие и контракт AgroMind. Они не измеряют распознавание реального мусора, огня или дыма.

## Хранение и доступ

Оригиналы и доказательства остаются на локальном диске, пока оператор сам их не удалит. Автоматического удаления/отправки нет. Веб-сервер штатно слушает `127.0.0.1`; не публикуйте его без аутентификации, лимитов и защищённого reverse proxy. Endpoint файлов разрешает только результаты и созданные JPEG evidence, не произвольные файлы/веса/оригиналы.
